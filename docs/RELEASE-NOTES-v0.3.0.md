# ClientGraph AI v0.3.0 版本说明

> 发布日期：2026-11-06
> 状态：集成回归完成，可公开演示（虚构数据）
> 回归范围：客户 360、项目/需求抽取、版本演化、冲突、风险、待办、通知、关系图、全局搜索

## 1. 本版新增

| 模块 | 能力 |
|---|---|
| `customer360/` | 客户身份、项目、需求、风险、待办、时间线、证据、最近跟进提醒 |
| `extraction/` | 从聊天/通话/邮件/文档抽取项目、阶段、需求、提出人、负责人、截止、预算、验收、待确认 |
| `requirement_history/` | 需求/项目追加式版本，保留首次出现、修改、确认、取消与前后证据 |
| `conflict_detection/` | 预算/工期/范围/负责人/平台/接口/权限/验收八类冲突，A/B 双方来源 |
| `task_center/` | 从明确下一步动作生成待办，完成/延期/重开/批量与提醒策略 |
| `relationship_view/` | 8 类实体关系图，区分直接证据、语义相似、人工确认 |
| `unified_search/` | 客户/项目/沟通/文档/需求/待办/证据统一检索 + 三类自然语言问答 |

## 2. 集成回归

数据：2 个客户（c1 青岚、c2 恒晟）、3 个项目（p1 设备巡检、p2 售后工单、p3 供应链协同）、聊天/通话/邮件/文档/需求/风险/待办/证据多来源。

| 检查 | 结果 |
|---|---|
| 客户 360 | c1 2 项目/2 需求/1 风险/3 待办/5 条时间线；c2 1 项目/2 需求/1 风险/1 待办/2 条时间线 |
| 时间线 | 按发生时间倒序，d4 缺失时间排最后 |
| 需求抽取 | c1 得到设备台账；c2 得到供应链协同；c2 无设备台账 |
| 版本演化 | p1 三个项目版本；预算 8 万→10 万、工期 11-15→12-01 |
| 冲突 | 2 个冲突，分别属于 p1/p3，均 `must_confirm` |
| 待办 | 4 条，跨 c1/c2；完成 T1 不影响 T3 |
| 通知 | 发送 T1 到期与 c2 无跟进；应用退出不伪造 |
| 关系图 | 27 节点、23 边，人工边 1；无 c1→p3、c2→p1 |
| 全局搜索 | 小程序开发仅 c1；供应链仅 c2；逾期 T1/T3；p1 变更 v2 |
| 控制台/检查 | 29 项检查全部通过 |

## 3. 失败与边界

- 未知查询返回 high，不编造证据。
- 无版本历史的项目变更返回 high。
- 模糊日期不写截止时间，生成待确认问题。
- 应用退出期间不发送、不标记通知已发送。
- 冲突不自动选择，`model_choice=null`、`write_blocked=true`。
- 同名客户/项目、跨客户相似需求只给语义建议，不合并。
- 共享文件多项目保留多条直接边。

## 4. 已知限制

- ASR 为 Mock；Qwen 未联调。
- OCR 依赖本地 RapidOCR，CPU 单页 3–19 秒。
- `.doc`/`.ppt` 依赖 LibreOffice；压缩包/微信数据库未解析。
- 2.1 GB / 200 页 OCR 为界面模拟，不是真实吞吐。
- 通知策略已实现，真实 Windows Toast 需桌面端接入。
- 关系图输出 JSON，未做可视化画布。
- 搜索意图为规则识别，换问法可能落兜底。
- 单机单用户，无账号/权限/云同步；审计与状态存本地。
