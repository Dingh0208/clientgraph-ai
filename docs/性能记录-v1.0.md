# 性能记录 v1.0

> 日期：2026-11-06
> 环境：Windows x64、Python 3.12.13、ffmpeg 7.1.1、本地 RapidOCR（CPU）、Mock ASR
> 说明：单次观测，不是压测结论；ASR 为 Mock，真实 Qwen 未联调。

## 1. 后端流水线

| 场景 | 输入 | 输出 | 耗时 |
|---|---|---|---|
| 1 小时音频 | 3,600,039 ms，44.1kHz 双声道 MP3（14.4 MB） | 16kHz 单声道；12 片；36 段 | **7,093 ms** |
| 8 秒短音频 | 8,000 ms，48kHz 双声道 | 1 片；3 段 | **478 ms** |
| 视频（6 秒） | 640×360，AAC 音轨 | 提取 16kHz 单声道；3 段；`frame_ocr=false` | **581 ms** |
| PDF 文本层 | 2 页，中英混排 | 4 个文本块；OCR 0 次 | **108 ms** |
| 扫描件倾斜 2.5° | 1 页，1240×1754 渲染 200 DPI | 3 块；平均置信度 0.9978 | **15,979 ms** |
| 混合中英文图片 | 1200×520 | 2 块；平均置信度 0.9965 | **6,209 ms** |
| 低清图片 | 320×200，模糊 3.0 | 0 块；`W_OCR_NO_TEXT` | **3,495 ms** |
| 空白页 | A4 空白 | 0 块；`W_EMPTY_PAGE` | **589 ms** |
| OCR 失败隔离 | 2 页，第 2 页引擎异常 | 第 1 页 2 块保留；`partial` | **15,415 ms** |

OCR 单页耗时主要来自模型初始化与 CPU 推理；首次加载约 3–5 秒，之后单页仍可能 6–16 秒。

## 3. 界面负载模拟

| 收尾 | 总预计剩余 28 秒 |

这些时间是**界面按速率估算**，不是真实 2.1 GB 文件的处理耗时；真实后端只测了上表的 1 小时音频、OCR 与文档。

## 4. 诊断服务

| 项 | 观察 |
|---|---|
| 诊断 API | 本地 127.0.0.1，单次检查约 0.3–1 秒（不含 OCR 模型导入） |
| Sidecar 启动成功 | 5 秒健康检查窗口内通过 |
| 启动失败 | 进程退出即返回，冷却 3 秒 |
| 最大尝试 | 2 次；第 3 次返回 `E_MAX_ATTEMPTS` |
| 端口冲突 | 不拉起，立即返回 `E_PORT_CONFLICT` |

## 5. 结论与限制

- 长音频耗时主要在 ffmpeg 归一化/切片；Mock ASR 几乎不占时间，真实 Qwen 时延未测。
- OCR 是当前最慢环节，CPU 单页 3–16 秒；批量 OCR 需要队列与限流。
- 文档解析为毫秒级，瓶颈在文件 IO 与格式复杂度，不在解析器。
- 界面 ETA 是产品体验估算，不是性能承诺。
- 以上均为单机单次观测，未做并发、内存、磁盘 IO 压测。
