## 1. 支持范围

| 类型 | 解析方式 | 保留内容 |
|---|---|---|
| DOCX | python-docx，按正文顺序读取段落与表格 | 段落/标题、表格行列、文档属性 |
| DOC（旧版） | 需 LibreOffice 转换；未安装则失败 | — |
| XLSX | openpyxl（缓存值） | 多工作表、行列、合并区域 |
| XLS | xlrd | 多工作表、行列 |
| PPTX | python-pptx | 幻灯片页码、文本框、表格、备注 |
| PPT（旧版） | 需 LibreOffice 转换；未安装则失败 | — |
| EML | 标准库 email | 发件人、收件人、抄送、时间、主题、正文、附件 |
| TXT | 编码探测 + 聊天识别 | 段落或聊天消息 |
| HTML | 标准库 HTMLParser | 文本、表格、聊天消息 |
| JSON | 标准库 json | 聊天消息或扁平化键值 |

统一输出：`text`（可搜索）、`blocks`、`messages`、`meta`、`errors`、`warnings`、`stats`。

## 2. 表格：保留行列

每个表格行是一个 block：

```json
{
  "type": "table_row",
  "table_id": "x1",
  "table_index": 1,
  "row": 2,
  "cols": ["EQ-001", "数控车床", "一车间", "在用"],
  "text": "EQ-001 | 数控车床 | 一车间 | 在用",
  "locator": "xlsx://devices.xlsx?sheet=%E8%AE%BE%E5%A4%87%E6%B8%85%E5%8D%95#table=1&row=2"
}
```

- `cols` 保留每一列，空单元格保留为空字符串；
- `row` 是原始行号（跳过全空行但仍保留行号）；
- 来源：
  - DOCX：`docx://文件#table=1&row=2`
  - XLSX：`xlsx://文件?sheet=名称#table=1&row=2`
  - XLS：`xls://文件?sheet=名称#table=1&row=2`
  - PPTX：`pptx://文件?slide=2#table=1&row=1`
  - HTML：`html://文件#table=1&row=1`

DOCX 表格按正文顺序与段落交错输出；合并单元格在 DOCX 中可能重复文本，不做去重。

## 3. PPT：保留页码

- 文本块带 `slide`（从 1 开始）与 `shape`；
- 表格行带 `slide`；
- 备注单独成块，`type=slide_note`；
- 定位：`pptx://文件#slide=2&shape=3`。

## 4. 邮件：保留头信息

`meta.email`：

```json
{
  "from": ["陈晓岚 <chen.xiaolan@example.com>"],
  "to": ["王工 <wang.gong@example.com>"],
  "cc": ["李副总 <li.fu@example.com>"],
  "date": "2026-09-29T10:12:00+08:00",
  "date_raw": "Tue, 29 Sep 2026 10:12:00 +0800",
  "subject": "需求文档 v1.0 请确认",
  "message_id": "<demo-001@example.com>",
  "body_format": "plain",
  "attachments": [{"filename": "巡检说明.txt", "content_type": "text/plain", "size_bytes": 12}]
}
```

- 正文优先 `text/plain`，没有时把 `text/html` 转纯文本；
- 附件只登记元数据，不写入磁盘；
- 定位：`mail://文件#part=text`、`#attach=文件名`。

## 5. 聊天：保留时间与发送者

### 5.1 TXT

支持两类常见格式：

```text
2026-09-22 09:14:02 陈晓岚
上次电话后我们内部过了一版
```

```text
[2026-09-22 09:14] 陈晓岚：上次电话后我们内部过了一版
```

规则：

- 时间 + 发送者 + 内容（冒号）为强匹配；
- 时间 + 发送者单独一行、下一行内容为弱匹配；
- 至少 3 条弱消息且同一发送者出现 ≥2 次，才判定为聊天，避免把普通文档里的日期行误判；
- 连续的非时间行并入上一条消息正文。

消息对象：

```json
{
  "id": "m001",
  "ts": "2026-09-22 09:14:02",
  "sender": "陈晓岚",
  "text": "上次电话后我们内部过了一版",
  "type": "text",
  "locator": "chat://chat.txt#msg=m001"
}
```

### 5.2 HTML / JSON

- HTML：先提取块级文本，再按同一套规则识别；
- JSON：识别 `messages / messageList / chat / data / list` 数组，映射常见字段：
  - 时间：`time / timestamp / createTime / msgTime / date / sendTime`
  - 发送者：`sender / from / nickname / senderName / talker / userName / name`
  - 内容：`content / text / msg / message / body`
- 至少 2 条且含时间或发送者才判定为聊天；
- 不是聊天的 JSON 会按叶子节点扁平化，路径写入 `locator`。

## 6. 失败与建议

| 代码 | 场景 | 建议 |
|---|---|---|
| `E_FILE_EMPTY` | 0 字节 | 重新导出文件 |
| `E_FILE_CORRUPT` | DOCX/XLSX/XLS 损坏 | 用 Office/WPS 打开后另存为新文件 |
| `E_LEGACY_FORMAT` | `.doc` / `.ppt` 且无转换器 | 另存为 `.docx` / `.pptx`，或安装 LibreOffice |
| `E_LEGACY_CONVERT_FAILED` | 转换失败 | 手动另存后重试 |
| `E_ENCODING` | 文本编码无法识别 | 另存为 UTF-8 或 GB18030 |
| `E_JSON_INVALID` | JSON 非法 | 检查语法，或按纯文本导入 |
| `E_UNSUPPORTED_FORMAT` | 扩展名不支持 | 使用支持的格式 |
| `E_PROCESS_FAILED` | 未预期错误 | 原始文件保留，可另存后重试 |

失败结果示例：

```json
{
  "status": "failed",
  "errors": [{
    "code": "E_FILE_CORRUPT",
    "message": "DOCX 无法打开：...",
    "hint": "请用 Word/WPS 打开后另存为新的 .docx；确认文件未加密或损坏。",
    "recoverable": true
  }]
}
```

无法解析时 `blocks` 与 `messages` 为空，`status=failed`，不会伪装成空文档。

## 8. 限制

- DOCX 不解析页眉页脚、脚注、批注、图片与文本框；表格合并单元格可能重复文本。
- XLSX 只读缓存值：公式没有缓存结果时为空；最多 5000 行 × 100 列，超出截断并警告。
- XLS 只做基础值读取，不保留格式、合并区域与公式。
- PPTX 不解析图表、图片、SmartArt 与动画；只保留文本、表格、备注。
- EML 不支持 `.msg`、加密邮件、内嵌图片渲染；HTML 正文转文本会丢失样式。
- HTML 解析为轻量实现：不执行 JS、不处理复杂嵌套表格与 CSS 隐藏内容。
- 聊天识别为启发式：时间/发送者写在 HTML 属性或非常规分隔符中时可能识别失败，退化为普通段落。
- JSON 只扁平化前 800 个叶子节点；聊天数组字段名需落在支持列表内。
- `.doc` / `.ppt` 转换依赖 LibreOffice；当前环境未安装，因此验证的是失败与建议路径。
- 不支持密码保护的 Office 文件。
