## 1. 性能与错误场景

导入中心内置 20 个文件的批量负载，覆盖：

| 场景 | 任务 | 规模 |
|---|---|---|
| 大文件 | F06 会议录屏 | 2.1 GB 视频 |
| 长音频 | F03 电话录音 | 62 分钟，13 个切片 |
| 大批量 | 20 个文件 | 聊天、音频、视频、PDF、OCR、Office、邮件 |
| OCR | F12 扫描合同 | 200 页 |
| 损坏文件 | F07 合同扫描件 | 120 页预期，解析阶段失败 |

界面按文件独立推进，阶段、进度、预计剩余同时展示。

### 1.1 实测采样（界面）

| 时间点 | 观察 |
|---|---|
| 批量开始 | 总预计剩余 5 分 14 秒 |
| 视频转写 33% | “转写 3/13 片 · 剩 2 分 54 秒” |
| 视频转写 66% | “转写 12/13 片 · 剩 1 分 28 秒” |
| 200 页 OCR 72% | “OCR 14/200 页 · 剩 1 分 7 秒” |
| 收尾 | 总预计剩余 28 秒 |
| 结束 | 已完成 16、待归档 3、失败 1、取消 0 |

说明：以上是**界面负载模拟**的进度与估算，不代表真实 2.1 GB 文件的处理耗时；真实后端已在长音频与 OCR 流程中单独验证（1 小时音频 12 片/36 段；OCR 单页约 3–19 秒）。

## 2. 阶段进度与预计剩余

| 类型 | 阶段显示 |
|---|---|
| 音频/视频 | 解析文件 → 转写 x/13 片 → 识别与归属 |
| PDF/扫描件/图片 | 解析文件 → OCR x/200 页 |
| 其他 | 解析文件 → 识别与归属 |

- 每个任务独立进度，不共享计数器；
- 预计剩余按“剩余单元 × 演示速率 ÷ 并发”估算，随后台任务减少；
- 总预计剩余显示在顶部，单任务显示在进度条下方；
- 失败任务显示失败点（如 35%），不继续累加。

## 3. 失败原因、重试与人工兜底

- 失败行显示错误码与可读原因：`E_CORRUPT：PDF 结构损坏，无法读取文本层（原件已保留）`；
- 提供“重试”，最多 2 次；达到上限后按钮消失；
- 提供“人工处理”抽屉：
  - 来源、类型、大小、状态、尝试次数、原件保留；
  - 针对错误码的处置建议（损坏、转写超时、OCR 低置信、切片失败、模型不可用）；
  - 重试；
  - 导出诊断（下载文本，包含任务、错误、阶段、时间）；
  - 转人工处理（标记 `manual=true`，停止自动重试，保留原件）。
- 转人工后行内显示“已转人工，自动重试已停止”。

验证：F07 在 35% 失败，其余 19 个任务全部进入完成/待归档；人工抽屉可打开、可标记，失败数保持 1。

## 4. 本地诊断

入口：侧栏「本地诊断」。数据来自本地 ops 服务：

```bash
python -m ops.server --port 8123
```

页面调用 `/api/diagnostics`，不使用假状态；服务未启动时显示**具体命令**和错误原因，而不是“服务不可用，请重试”。

### 4.1 五个组件

| 组件 | 检测内容 | 状态/帮助 |
|---|---|---|
| Sidecar | TCP 端口、`/health` 响应、启动命令是否配置 | 未启动/降级/正常；端口冲突、日志、启动步骤 |
| 微信引擎 | `CG_WECHAT_ENGINE` 路径、`--version` | 未安装/异常/正常；文件导入兜底 |
| ffmpeg | `ffmpeg`、`ffprobe` 路径与 `-version` | 未安装/正常；安装与 PATH 步骤 |
| OCR | PyMuPDF / Pillow / RapidOCR 导入与版本 | 未安装/正常；pip 安装命令 |
| ASR | provider、模型、密钥是否设置（不展示密钥） | Mock 降级、Qwen 未配置、正常 |

### 4.2 当前环境实测

### 4.3 手动启动与拉起失败策略

用测试用假 Sidecar（`scripts/fake_sidecar.py`，仅验证诊断，不是产品组件）验证：

| 操作 | 结果 |
|---|---|
| 未启动 → 点击启动 | `ok=true`，状态变为“正常”，health 返回 `{"ok":true}` |
| 组件已健康 | 返回“已在运行，直接接管”，不重复拉起 |
| 端口被占用且健康检查失败 | `E_PORT_CONFLICT`，不重复启动，提示结束冲突进程 |
| 启动命令未配置 | `E_NOT_CONFIGURED`，提示配置命令或用文件导入 |
| 启动命令立即退出 | `E_START_FAILED`，返回日志尾部，冷却 3 秒 |
| 冷却期内再次启动 | `E_COOLDOWN`，提示剩余秒数 |
| 连续失败 2 次 | `E_MAX_ATTEMPTS`，停止自动尝试，要求查看日志或手工处理 |

日志写入 `ops-logs/<组件>.log`，界面“查看日志”展示尾部；不记录密钥。

### 4.4 帮助信息

每个组件卡片都有可展开的“帮助与修复”列表，例如：

- Sidecar：启动、端口冲突、安装目录与杀毒软件；
- 微信引擎：安装路径、版本检查、文件导入兜底；
- ffmpeg：winget 安装、PATH、版本确认；
- OCR：pip 安装、模型完整性、低置信度人工核对；
- ASR：Mock 与 Qwen 区别、密钥配置、限流与端点。

## 5. 限制

- 导入中心的 2.1 GB 视频、62 分钟音频、200 页 OCR 是**界面负载模拟**；真实处理能力见长音频/媒体/文档流程的独立测试。
- 预计剩余是按配置速率估算，不是对真实磁盘、CPU、网络的实时测量。
- Sidecar 与微信引擎未随本仓库交付；手动启动依赖 `CG_SIDECAR_CMD_JSON` / `CG_WECHAT_ENGINE` 配置。当前使用的是测试假 Sidecar。
- OCR 依赖当前未安装，所以真实状态为“未安装”，不是伪造“正常”。
- ASR 仍为 Mock；Qwen 未配置、未联调，不能宣称真实识别。
- 诊断服务仅绑定 127.0.0.1，无鉴权；不要暴露到公网。
- 审计/日志为本地文件，不是不可篡改日志系统。
