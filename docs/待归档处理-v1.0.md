> 日期：2026-11-06

## 1. 定位

「待归档」是**独立处理界面**，不是导入中心的一部分：

- 导入中心只负责文件进入、进度、失败与重试；
- 待归档负责“这份资料到底属于谁”的判断与确认；
- 两个视图有各自的导航、列表与操作，导入中心不提供归档按钮，只提供跳转入口。

## 2. 匹配规则

按优先级从高到低：

| 优先级 | 规则 | 置信度 | 结果 |
|---|---|---|---|
| 100 | 手机号（归一化数字后完全相等） | 0.99 | 唯一候选时预选客户 |
| 100 | 邮箱（小写后完全相等） | 1.00 | 唯一候选时预选客户 |
| 100 | 微信标识（小写后完全相等） | 0.99 | 唯一候选时预选客户 |
| 50 | 客户名称 / 别名出现在标题或摘要 | 0.70 | 仅作建议，不预选 |

判定：

- 精确候选 = 1 → `exact`，预选客户；该项目只有 1 个项目时同时预选项目；
- 精确候选 ≥ 2 → `multi`，列出全部候选，不预选；
- 无精确候选但有名称建议 → `suggested`，只展示建议；
- 无任何候选 → `none`，提示新建客户。

所有待处理项都停留在待归档，**确认前不写入客户档案**，避免精确匹配被当成自动归档。

## 3. 状态与操作

```text
待处理 pending
 ├── 逐条确认 / 批量确认 → 已归档 archived
 ├── 逐条忽略 / 批量忽略 → 已忽略 ignored
 └── 新建客户 → 仍为待处理（选中新客户）
已忽略 ignored ── 恢复 → 待处理
```

### 3.1 逐条确认

每行提供：客户下拉、项目下拉、负责人下拉、确认归档、忽略、新建客户、记录。

- 客户有项目时，必须选择项目才能确认；
- 客户没有项目时，允许“不指定项目”；
- 负责人默认“王工（我）”，可选其他负责人；
- 操作人固定为当前用户“王工（我）”，与负责人分开记录。

### 3.2 批量确认

勾选多条后，在批量栏选择客户、项目、负责人：

- 项目列表随客户联动；
- 客户有项目时必须选择项目；
- 一次操作对全部勾选项写入相同目标，但每条独立记录操作时间与来源；
- 批量忽略同理。

### 3.3 新建客户

弹窗填写名称（必填）、公司、手机号、邮箱、微信标识：

- 创建后立即加入客户列表并选中；
- 新客户没有项目，可直接“不指定项目”归档；
- 新建动作写入该资料的记录，再归档时追加归档记录；
- 手机号 / 邮箱 / 微信会成为后续精确匹配依据。

### 3.4 忽略与恢复

- 忽略不删除资料，状态改为已忽略，原因默认“人工忽略”；
- 「已忽略」分组可见并恢复为待处理；
- 恢复保留原来源、原标识与历史记录；
- 不做物理删除。

## 4. 审计字段

每次归档 / 忽略 / 恢复 / 新建客户都写入：

| 字段 | 内容 |
|---|---|
| 操作 | 确认归档 / 批量归档 / 忽略 / 恢复 / 新建客户 |
| 操作人 | 王工（我） |
| 时间 | ISO 时间，界面本地化显示 |
| 来源 | 来源类型 + 文件名，如“电话 · 未知号码录音-1011.amr” |
| 目标 | 客户 / 项目 / 负责人（归档时） |
| 说明 | 归档去向或忽略原因 |

归档对象本身另存 `sourceFile`、`sourceChannel`，即使后续客户改名也能追溯来源。

## 5. 界面

- 侧栏新增「待归档」，独立视图 `view-archive`；
- 顶部统计：待处理、多候选、无匹配、已归档、已忽略；
- 分组：待处理 / 已归档 / 已忽略；
- 待处理列表展示：来源、收到时间、摘要、标识、候选标签、匹配结果；
- 已归档展示：归档目标、负责人、操作人、时间、来源；
- 已忽略展示：忽略原因、操作人、时间、恢复按钮；
- 导入中心只保留一行说明与跳转按钮，不出现归档操作。

## 7. 限制

- 这是前端原型：没有后端权限、账号体系与不可篡改审计日志；操作人是固定值。
- 数据保存在浏览器 localStorage，换浏览器或清缓存会丢失；仅适合演示。
- 匹配只做手机号 / 邮箱 / 微信精确相等与名称包含；昵称、简称、错别字、大小写之外的变体不覆盖。
- 名称命中只做建议，不自动选中，避免同名客户误归档。
- 客户有项目时强制选择项目；“不指定项目”只用于没有项目的客户。
- 批量操作对全部勾选项写入同一目标，不支持批量后再逐条覆盖（可先批量、再对单条重新归档）。
- 忽略是软状态，不删除原件；原型没有“永久删除”入口。
- 归档后的资料不会自动写入客户时间线（原型未实现该联动）。
