# ClientGraph AI 产品基线 v0.1.0

> 日期：2026-11-06
> 状态：原型基线，冻结范围为 v0.1.0
> 对应代码：`prototype/index.html`

## 1. 一句话定位

把电话、微信、邮件、文件里的客户信息聚合成一个可追溯的工作台，让老板快速回答：**这个客户是谁、聊过什么、需求是什么、现在卡在哪、下一步做什么。**

## 2. 目标用户

| 维度 | 描述 |
|---|---|
| 身份 | 软件公司老板 / 经营者，单人多项目 |
| 环境 | Windows 桌面浏览器；日常电话、微信、邮件混合沟通 |
| 能力 | 普通办公软件水平，不接受复杂配置 |
| 诉求 | 不遗漏信息、快速回顾、看清缺口、知道下一步 |
| 边界 | 单用户、单机；不做团队协作与客户侧账号 |

## 3. 产品闭环

```text
导入 → 理解 → 关联 → 演化 → 行动 → 追踪
```

v0.1.0 只覆盖其中一段：**理解结果的检索、关联视图、证据定位、缺口呈现**。其余环节在路线图中，不在本版本宣称范围内。

## 4. 本期范围（v0.1.0）

| 编号 | 能力 | 验收口径 |
|---|---|---|
| S1 | 资料问答 | 返回原文依据与来源；无依据时明确未知 |
| S2 | 跨模态引用 | 至少覆盖聊天、通话、邮件、文档、表格、扫描件中的 4 类；点击可见定位符 |
| S3 | 客户 / 项目概览 | 客户 2 个、项目 3 个、资料 12 份、需求 6 条可核对 |
| S4 | 信息缺口 | 5 项缺口 / 冲突，按“必须先确认 / 重要”分级，带双方证据 |
| S5 | 未知问题 | 不相关提问返回未知，不产生引用 |
| S6 | 敏感拒答 | 命中敏感模式时拒绝，响应中不出现号码 |

## 5. 非目标（本版本明确不做）

- 不做模型调用、不做生成式回答、不做嵌入与向量检索；
- 不做文件导入、解析、ASR、OCR；
- 不做需求版本、回写、待办、提醒；
- 不做账号、权限、多人协作、云同步；
- 不做移动端适配；
- 不宣称生产可用性或安全合规能力。

## 6. 设计原则

1. **证据优先**：先给原文与定位，再谈结论；没有依据就说不知道。
2. **只读**：原型不写业务数据，避免“问答即改库”。
3. **可核对**：每个数字都能在页面或资料清单中复算。
4. **单机**：无网络、无外部依赖，便于评审与复现。
5. **边界诚实**：能力与限制写在 README 与 LIMITATIONS 中，不用演示效果代替真实能力。

## 7. 成功标准（v0.1.0）

- 7 项冒烟检查全部通过，控制台 0 错误；
- 任一答案都能点回来源与定位；
- 未知与敏感两类边界行为可稳定复现；
- 评审者无需安装依赖即可在 1 分钟内打开并复现演示脚本。

## 8. 架构（原型）

```text
单文件 HTML
├── 静态数据集（12 份资料 / 51 个片段 / 6 条需求 / 5 项缺口）
├── 中文二元组 + IDF 检索（无模型）
├── 证据定位符（chat:// file:// mail:// doc:// xls:// pdf:// ppt:// img://）
└── 原生 DOM 渲染与抽屉交互
```

无后端、无数据库、无构建链路；刷新即重置。

## 9. 下一版候选（不承诺）

- 接入真实导入与解析，保留当前证据定位符协议；
- 增加需求版本与变更建议；
- 引入模型时保持“检索结果 + 引用”优先，禁止无证据生成；
- 增加可持久化的澄清单与导出。
