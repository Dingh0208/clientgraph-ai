# 限制说明 v0.1.0

> 本版本是交互原型，用于验证“资料 → 证据 → 问答 → 缺口”的界面与行为，不代表生产能力。

## 1. 能力边界

| 项 | 现状 | 影响 |
|---|---|---|
| 问答方式 | 中文二元组 + IDF 检索，不做语义理解 | 同义词、改写、跨句推理会漏检 |
| 生成能力 | 不调用模型，不生成结论 | 回答是原文摘录，不是总结 |
| 语料规模 | 12 份资料 / 51 个片段 | 不能代表真实数据量下的效果 |
| 资料导入 | 无 | 不能导入用户文件，只能使用内置语料 |
| 解析能力 | 无 ASR / OCR / 文档解析 | 图片与扫描件仅保留占位片段 |
| 需求演化 | 无版本、无变更建议 | “审批范围变化”为预置展示，不是自动识别 |
| 缺口识别 | 5 项为人工整理 | 不是自动冲突检测 |
| 持久化 | 无数据库、无 localStorage | 刷新即重置，不能保存操作 |
| 账号与权限 | 无 | 不能多人使用，不能控制数据范围 |

## 2. 检索质量

- 停用词表为手工维护，覆盖“有没有 / 提到 / 是否”等常见问法，仍可能漏掉其他虚词。
- 阈值固定（0.9），对不同长度的问题不够自适应。
- 中文分词采用二元组，专有名词与缩写（如 ERP、P0）依赖原文字符串匹配。
- 结果上限 4 条，可能截断同一主题的其他证据。
- 不做去重合并：同一事实在多份资料出现时会重复展示（这在证据场景是有意保留的）。

## 3. 敏感数据拒答

- 基于正则匹配手机号、身份证、银行卡、账号、密码、联系方式等模式。
- 只覆盖常见格式，不能识别拼音、分隔符变形、图片中的号码或隐喻表达。
- 拒答是**产品行为演示**，不是安全控制；生产环境需要字段级权限、脱敏存储与审计。

## 4. 证据与真实性

- 定位符为逻辑定位，原型不打开原始文件；`file://M02#02:10` 等不是真实文件路径。
- 证据摘录来自内置虚构语料，不能用于任何真实客户判断。
- 本仓库不包含截图；测试证据为页面文本与 DOM 状态的实际读取结果。

## 5. 兼容性与性能

- 仅在 Chromium 156 验证；未测试 Firefox、Safari、移动端。
- 未做 1,000+ 资料、10,000+ 片段下的性能测试。
- 未做无障碍（键盘导航、读屏）专项验证。
- 单文件约 30 KB，首屏无网络依赖，加载开销可忽略。

## 6. 合规与发布

- 不含真实个人信息、商业秘密、平台密钥或客户资料。
- 演示公司名均带“（虚构）”，电话与邮箱为占位格式。
- 未经书面许可不得用于对外商业宣传或作为交付承诺。
