# 存储迁移 v1.0（schema 1 → 2）

> 版本：v0.5.0 · 2026-11-08
> 代码：`ops/storage_migration.py`
> 证据：`evidence/storage-migration-v0.5.0.json`、`evidence/deployment-migration-v0.5.0.json`

## 1. 背景

目标环境为单机单用户 Web，**没有关系型数据库**。持久化只有两类本地状态：

- `secure.json`：密码哈希、会话密钥、模型密钥、设置；
- `data/jobs/*.json`：上传任务与阶段结果。

因此本次“数据库迁移”实际是本地状态 schema 迁移，不执行 SQL，不创建数据库。

## 2. 迁移内容

| 对象 | v1 | v2 |
|---|---|---|
| `secure.json` | `schema=1`，无 `storage_version` | `storage_version=2`、`schema_version=2`、`migrated_at`、`migrations[]` |
| `data/jobs/*.json` | 无 schema 字段 | `schema_version=2`、`stage_count`、`migrated_at` |

不修改：

- 密码哈希、会话密钥、模型密钥；
- 设置项、上传任务状态、阶段结果；
- 已完成/失败/取消状态。

## 3. 执行

```bash
python -m ops.storage_migration --config-dir <配置目录>
```

输出 `migration-v2.json`：

```json
{
  "status": "ok",
  "from_version": 1,
  "to_version": 2,
  "secure": "migrated",
  "jobs": {"scanned": 0, "migrated": 0, "skipped": 0, "backed_up": 0}
}
```

- 首次运行备份：`secure.v1.bak.json`、`J1.json.v1.bak`；
- 第二次运行返回 `secure=already_current`，不重复写；
- 配置损坏时返回 `E_STORAGE_CORRUPT`，不静默重置。

## 4. 验证

`python scripts/verify_storage_migration.py`，10 项通过：

- 密钥原值不变；
- 设置、任务阶段保留；
- 备份存在；
- 报告不含密钥；
- 二次运行幂等。

## 5. 限制

- 没有 SQL 数据库，不涉及表结构、索引、数据回填；
- 备份文件保留在配置目录，需要按本机权限保护；
- 迁移只处理当前两种 JSON 状态，不覆盖未来新增存储；
- 旧版 v0.4.0 不读取 `storage_version`，回滚后仍可运行。
