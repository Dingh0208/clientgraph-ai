## 2. 详细记录

### F1 不可读资料

- 场景：选择一份损坏的 PDF，`readable=false`；
- 期望：发送分析前就阻止，不允许“先跑再报错”；
- 实际：`start_analysis` 返回 `E_UNREADABLE`，工作单停留在草稿，`error_message` 保留文件名；
- 处理：不删除该工作单，作为不可读样本保留；
- 教训：不可读检查必须在建批次之前，不能产生半成品批次。

### F2 批次超时与重试

- 场景：模型批次模拟超时；
- 期望：单批失败不阻塞其他批次，失败原因可追溯，可只重试失败批次；
- 实际：状态为未完成，`batch_errors` 记录 `E_MODEL_TIMEOUT`；`retry_failed` 只把失败批次重置为待执行，成功后工作单完成；
- 教训：重试不能清空错误历史，也不能重跑已成功批次。

### F3 未回答生成追问

- 场景：问题状态为已问、没有回答，直接调用“基于回答生成追问”；
- 期望：拒绝，因为没有“回答”可依据；
- 实际：`E_NOT_ANSWERED`，不产生子问题；
- 教训：追问的前置条件是已回答，不是已问。

### F4 未确认保存

- 场景：预览生成后不勾选确认直接保存；
- 期望：零写入；
- 实际：`E_CONFIRM_REQUIRED`，需求、版本、操作记录数量均不变；
- 教训：确认是独立步骤，不能由“已经预览过”替代。

### F5 预览被篡改

- 场景：修改预览中的字段值后提交；
- 期望：预览令牌校验失败，拒绝保存；
- 实际：`E_PREVIEW_TAMPERED`；
- 教训：预览与保存之间必须用摘要绑定，不能信任前端回传内容。

### F6 目标记录已变化

- 场景：生成预览后，需求描述被其他人修改；
- 期望：拒绝保存，避免覆盖别人改动；
- 实际：`E_TARGET_CHANGED`；
- 教训：保存前必须校验目标指纹，不能只看预览自身。

### F7 重复提交

- 场景：同一预览保存成功后再提交一次；
- 期望：拒绝，避免重复建需求/重复加版本；
- 实际：`E_ALREADY_APPLIED`；
- 教训：预览 ID 需要一次性使用记录，不能只靠按钮置灰。
