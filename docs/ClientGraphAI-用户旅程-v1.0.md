## 1. 闭环定义

**结论：闭环成立，且必须以“状态机 + 证据链”落地，问答只是读取层。**

### 1.1 六个环节

| 环节 | 要解决的问题 | 关键产物 | 判断这一环是否真的闭合 |
|---|---|---|---|
| 导入 | 资料进得来、不丢失、不重复 | 原件 + SHA-256 + 类型 + 处理状态 | 任何渠道都有唯一记录，失败可重试 |
| 理解 | 资料变成可核对的结构 | 转写片段、7 字段摘要、需求候选、文档解析 | 每个结论都能点回原文/时间点 |
| 关联 | 资料挂到正确的客户和项目 | 客户/项目归属、时间线、待归档 | 精确匹配才自动，模糊只给候选 |
| 演化 | 新信息改变旧结论而不覆盖历史 | 需求版本、变更建议、冲突、回答回写 | 旧值保留，diff 可查，变更可拒绝 |
| 行动 | 结论变成可执行动作 | 待办、澄清单、对外问题、导出件 | 每个动作都有来源和负责人 |
| 追踪 | 动作有结果、结果再进下一轮 | 状态、提醒、完成判定、指标 | 未完成会浮现，完成了会回流 |

### 1.2 五个时刻与六环的映射

| 用户时刻 | 实际经过的环节 |
|---|---|
| 通话结束后归档 | 导入 → 理解 → 关联 → 行动 |
| 客户复盘 | 关联 + 理解（读取已存证据，不新增） |
| 需求变化追踪 | 演化（版本、冲突、变更建议） |
| 需求澄清 | 演化 → 行动（缺口变成问题清单） |
| 下一步跟进 | 行动 → 追踪（待办、提醒、回写） |

五个时刻不是五个功能，而是同一条状态机的五个切面。用户感知到的是五个场景，系统内部只有一条不断向前、可回退、可追溯的数据流。

### 1.3 设计约束：不是问答机器人

问答机器人只有“理解”和“检索”，没有归属、没有版本、没有确认点、没有状态。ClientGraph AI 的差异在四件事：

1. **有归属**：跨客户、跨项目不串线，未归属单独成区，拆分只改归属不重生成。
2. **有证据**：每个结论带原文摘录、来源、时间与跳转定位；原件删除后快照仍可读。
3. **有版本**：需求有版本历史，旧值不被覆盖，变更可被拒绝，冲突不由模型裁定。
4. **有动作**：可回写需求、更新项目、生成待办、到期提醒，不是答完就结束。

由此得到两条产品级规则：

- **问答层只读**：AI 问答只检索与解释已有的关联数据，不允许在对话中静默改库。
- **写入只走工作单**：任何写操作必须经过需求澄清单、变更建议或预览确认面板，并留下来源。

**功能判定标准**：任何新功能若不能明确落到六环中的某一环，并产出可追踪的产物，就不进入当前版本。

## 2. 旅程总览

场景设定：一次 35 分钟客户通话为起点，T+5 分钟完成归档，T+1 天见客户前复盘，T+2 天出现需求变化，T+3 天发出澄清问题，之后进入跟进与下一轮。

| 步骤 | 所属环节 | 触发 | 完成判据（阶段门） |
|---|---|---|---|
| S1 导入登记 | 导入 | 通话结束、录音落到电脑 | 有文件记录 + 处理状态 |
| S2 转写与摘要 | 理解 | 导入成功且 AI 开启 | 摘要 7 字段齐全，空值有明确文案 |
| S3 归属关联 | 关联 | 理解完成或匹配返回 | match_status = matched |
| S4 归档落地 | 行动 | 归属确认 + 摘要确认 | 时间线可见 + 待办/需求候选已处理 |
| S5 见前复盘 | 关联 + 理解复用 | 约见/报价前主动打开 | 一屏能答“是谁、聊过什么、要什么、到哪、下一步” |
| S6 需求演化 | 演化 | 新沟通完成理解 | 变更建议已处理，版本号递增 |
| S7 需求澄清 | 演化 → 行动 | 范围/报价/工期需甲方确认 | 问题有证据，可对外交付 |
| S8 回答回写 | 演化 | 回答录入后老板决定回写 | 需求/项目字段有依据地变更 |
| S9 跟进追踪 | 行动 → 追踪 | 待办到期、澄清单未完成 | 有结果或明确延期，不静默消失 |
| S10 复盘收口 | 追踪 → 导入 | 每周固定时点或下一轮沟通前 | 本轮未决项全部有归属或结论 |

## 3. 分步设计

### 3.1 S1 通话结束 → 导入登记（导入环）

- **触发条件**：通话挂断，录音从手机/录音笔导出到电脑；或老板直接拖入、批量选择、粘贴。
- **输入资料**：mp3 / m4a / wav / amr / aac / flac 原件；可选通话时间、对方号码、备注；可手选客户/项目。
- **输出结果**：`files` 记录（内容哈希、原名、大小、类型、存储路径）+ `communications` 记录（channel=call、occurred_at、match_status=pending）+ 导入队列状态。
- **来源证据**：原件只读保留、SHA-256 去重、导入时间、文件元数据、通话时间；后续所有结论都指向这条沟通 ID。
- **人工确认点**：重复文件选“跳过/重新解析”；无匹配时选“新建客户/选择已有/放入待归档”；批量导入逐条确认归属。
- **失败状态**：格式不支持（如 .exe）、文件损坏、数据目录不可写、磁盘不足、压缩包超 2GB 或超 2,000 文件。
- **可恢复动作**：原件保留并标“不支持解析”可手动备注；单文件失败不影响同批其他文件；失败项一键重试；待归档 30 天内可恢复。

**阶段门 G1**：文件已可预览，处理状态明确，且不存在“未知状态”的记录。

### 3.2 S2 转写与摘要（理解环）

- **触发条件**：导入成功且 AI 自动导入开启；关闭时由老板在需求澄清中明确启动分析后才转写。
- **输入资料**：音频原件；超 30 分钟自动切 5 分钟片、重叠 5 秒；客户/项目信息只用于归属，不进入摘要依据。
- **输出结果**：带 `start_ms / end_ms / speaker_role` 的片段、全文、7 字段摘要 JSON、置信度、摘要版本 v1。
- **来源证据**：每字段 `evidence`（原话 + 时间戳），点击跳音频对应时间点；模型与提示词版本、说话人校正记录一并留痕。
- **人工确认点**：校正“我/客户”角色；编辑摘要保存为人工版本，AI 不覆盖；重新生成需二次确认，不删除人工修改。
- **失败状态**：方言或噪声导致识别差、供应商不支持说话人分离、模型未配置、JSON 被截断或非法、网络中断。
- **可恢复动作**：失败片段隔离重试；先切 Mock 跑通链路；关闭思考模式或换模型重跑；JSON 纠正一次仍失败则保留原数据并提示重试；人工先改角色再重跑。

**阶段门 G2**：每个摘要字段要么有证据，要么明确写“未提及 / 未明确下一步 / 本次沟通未形成明确结论”。

### 3.3 S3 归属关联（关联环）

- **触发条件**：转写/解析完成，或异步客户匹配返回。
- **输入资料**：手机号、邮箱、微信号/唯一标识、昵称、参与者、文件名、会话 username、历史客户库。
- **输出结果**：`customer_id / project_id`、`match_status`（matched / pending / unmatched）、候选列表、时间线挂载结果。
- **来源证据**：记录“命中了哪一个字段”的精确匹配依据、匹配时间、人工改选记录、候选来源。
- **人工确认点**：多个字段指向不同客户时进“待确认”并列候选；仅姓名/公司相似只给建议，绝不自动合并；新建客户；批量归档到同一客户。
- **失败状态**：完全无匹配；一号多人；同一客户重复建档；聊天账号归属不明导致跨客户串档。
- **可恢复动作**：进待归档 → 选已有/新建/忽略（保留 30 天可恢复）；手动合并客户并迁移项目/沟通/需求/待办、保留合并日志与副客户快照；身份不明确时保持独立，不猜测合并。

**阶段门 G3**：资料有且只有一个明确归属，或明确停在待归档区并带原因。

### 3.4 S4 归档落地（行动环）

- **触发条件**：归属确认完成，摘要已校对。
- **输入资料**：摘要“下一步动作”、聊天承诺、邮件正文、人工补录；项目现有进展文本。
- **输出结果**：客户 360 新增一条时间线；需求候选（默认待确认）；待办（含截止时间、优先级、来源沟通）；项目进展建议（自由文本 + 标签）。
- **来源证据**：需求候选带原文摘录与置信度；待办带 `source_communication_id`；进展建议带依据；低于 0.6 的只显示为“建议”，不入清单。
- **人工确认点**：需求候选逐条确认才进需求清单；待办一键加入或编辑；进展建议采纳/忽略；项目归属可改。
- **失败状态**：摘要无下一步、抽取置信度低、时间无法解析、客户/项目尚未确定。
- **可恢复动作**：手动新建待办；未确认的留在“待确认需求”池；稍后补归属；空值显示“未明确下一步”，不编造。

**阶段门 G4**：老板能在 1 分钟内说清“这次谈了什么、下一步谁做什么”，且每个动作可点回原话。

### 3.5 S5 见客户前复盘（读取环）

- **触发条件**：约见前、报价前、老板主动搜索，或首页“最近联系”进入。
- **输入资料**：客户 360 的画像、跨渠道时间线、未关闭需求、冲突提醒、待办、文件。
- **输出结果**：一屏结论——这个客户是谁、聊过什么、需求是什么、现在到哪一步、下一步做什么；可导出客户档案 PDF。
- **来源证据**：每条摘要可展开原文与录音时间点；画像结论标“AI 推断”并附来源；时间线可按渠道/项目/日期筛选。
- **人工确认点**：画像可编辑保存为人工版本；提示“画像可能已过时”时决定是否更新；冲突按“以 A 为准 / 以 B 为准 / 都保留 / 忽略”处理。
- **失败状态**：时间线超过 1,000 条卡顿、画像过时、某次沟通缺摘要、客户重名打开错档。
- **可恢复动作**：虚拟滚动/分页；重新生成画像；跳回原沟通补摘要；用手机号或公司名二次核对客户。

**阶段门 G5**：复盘结束时，老板能指出至少一个“本次要确认/要推进”的事项，并可直接落成待办或澄清单。

### 3.6 S6 需求变化追踪（演化环）

- **触发条件**：新通话/聊天/邮件/文档完成理解；或澄清回答准备回写。
- **输入资料**：新沟通的结构化结果 + 该项目既有需求清单、版本历史、项目预算与时间文本。
- **输出结果**：需求变更建议（新增/修改/取消）、新版本快照（v1 → v2）、冲突记录（预算/时间/范围/决策人）、项目进展建议。
- **来源证据**：变更前后 diff、触发变更的沟通 ID 与原文摘录、时间；冲突必须双方各自带证据，不允许单边裁定。
- **人工确认点**：每条变更建议确认后才生成新版本；取消需求需确认；冲突四选一；旧值永不自动覆盖。
- **失败状态**：新旧表述无法对齐、同一需求被重复抽取、冲突一方缺时间、模型把“补充说明”误判为“变更”。
- **可恢复动作**：保留旧版本可对比；忽略建议；合并重复需求；冲突选“都保留”等下次沟通；手动填写变更原因。

**阶段门 G6**：需求清单能回答“这条需求什么时候改的、被谁改的、依据是哪句话”。

### 3.7 S7 需求澄清（演化 → 行动）

- **触发条件**：范围、报价或工期需要甲方确认；资料出现关键缺口或相互矛盾；约见前需要准备问题。
- **输入资料**：老板手动勾选的已有资料（可跨客户/项目/未归属）、文本快照、可读性状态、默认文本模型、生成语言。
- **输出结果**：需求澄清单（草稿/分析中/部分完成/未完成/已完成/归档）；按客户/项目分区、三级优先级、10 个固定维度的问题；事实/推断/缺口/冲突标记；追问；对外仅含问题的文本与 Word/PDF。
- **来源证据**：每题保存提问理由 + 原文摘录 + 来源名称 + 来源时间 + 跳转；低置信度标注待核验；资料快照保证原资料删除后仍可追溯。
- **人工确认点**：发送前逐份确认范围、资料名称/类型/可读性、模型、语言；不可读资料移除；问题可编辑/删除/不适用/自定义；回答后手动触发追问；回写前预览确认。
- **失败状态**：资料不可读、超长分批中断、模型未配置/超时/坏 JSON、部分批次失败、整次分析无可用结果。
- **可恢复动作**：移除或重选资料；保留已完成批次续跑剩余批次；沿用原模型快照重试；失败不删原件、不覆盖旧单；再次分析新建单并保留旧快照。

**阶段门 G7**：对外版本只含问题且措辞可直发甲方；内部版本每题都能点回证据。

### 3.8 S8 回答回写（演化环）

- **触发条件**：甲方回答录入（已问 → 已回答），老板判断可以固化。
- **输入资料**：问题、回答、证据、目标客户/项目、现有需求与项目字段。
- **输出结果**：新需求（默认待确认、默认 P1）或项目字段更新；回写记录（来源澄清单 + 问题 + 回答 ID）；需求新版本。
- **来源证据**：回答原文、录入时间、字段映射依据、确认动作、变更前后值；回写结果可反查到具体问题。
- **人工确认点**：选择目标客户/项目；预览将改字段、字段证据与保持不变字段；确认保存；需求范围确认后才从待确认转已确认。
- **失败状态**：目标客户/项目已删除、字段与现状冲突、部分保存失败、回答含糊无法映射。
- **可恢复动作**：阻止保存并要求重选目标；只填有依据字段；逐项保存保留成功项、失败项单独重试；回答补充后再回写。

**阶段门 G8**：任一字段的新值都能反查到“哪次提问、哪句回答”。

### 3.9 S9 下一步跟进与追踪（行动 → 追踪）

- **触发条件**：待办创建或到期、澄清单未完成、需求状态变化、每天打开首页。
- **输入资料**：待办、需求、澄清单状态、冲突、客户最后联系时间、分析指标。
- **输出结果**：今日/逾期/本周视图、09:00 Windows 通知、未完成澄清单提醒、逾期标红、首页聚合、下次复盘入口。
- **来源证据**：待办来源沟通/澄清单、完成时间、延期记录、通知发送记录、状态变更日志。
- **人工确认点**：完成/取消/延期/编辑；标记“已跟进”；关闭提醒；归档澄清单；确认需求状态流转。
- **失败状态**：应用退出期间不发通知、免打扰时段覆盖、系统通知被禁用、任务堆积、逾期长期无人处理。
- **可恢复动作**：启动后补发到期提醒；应用内红点兜底；手动改期；离线队列恢复后重试；逾期待办保留，不自动关闭。

**阶段门 G9**：今天该做的事在首页首屏可见，逾期不会静默消失。

### 3.10 S10 复盘收口（追踪 → 导入）

- **触发条件**：每周固定时点，或下一轮沟通前。
- **输入资料**：本周新增沟通、需求变更、未回答澄清问题、逾期待办、待处理冲突。
- **输出结果**：本周变化视图（客观聚合，不是自动生成的周报文案）、下周待办、待补澄清清单、需要重新确认的客户。
- **来源证据**：每条变化带时间范围与来源沟通/澄清单，可逐条下钻。
- **人工确认点**：关闭已失效项、升级优先级、延后、归档客户或项目。
- **失败状态**：本周无数据、指标口径不全、变化太多无法收敛。
- **可恢复动作**：手动调整时间范围；按客户/项目收窄；导出后线下处理；未处理项自动滚入下周。

**阶段门 G10**：本轮结束时可明确回答“哪些事推不动、卡在谁那里、下一轮从哪开始”。
