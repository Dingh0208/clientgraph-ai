> 日期：2026-11-06

> 代码：`unified_search/`、`scripts/verify_unified_search.py`
> 证据：`evidence/unified-search-2026-11-06.json`

## 1. 检索范围

| 实体 | 索引内容 | 定位 |
|---|---|---|
| 客户 | 姓名、别名 | 最近沟通 locator；无则 `customer://id` |
| 项目 | 项目名 | 最近沟通 locator；无则 `project://id` |
| 沟通 | 标题、聊天/转写/邮件正文 | `chat://` / `call://` / `mail://` |
| 文档 | 标题、正文 | `doc://` |
| 需求 | 标题、描述 | 需求 locator 或来源证据 |
| 待办 | 标题 | 来源 locator |
| 证据 | 原文 | 原 locator |

关键词检索对中文按二元组匹配，结果按命中词数、时间排序；每条结果必须带 `locator`，否则不进入结果。

## 2. 自然语言问题

| 意图 | 识别 | 输出 |
|---|---|---|
| 客户提及 | “哪些客户提过/谁提过” | 客户、项目、结论、证据、时间、不确定性 |
| 项目变更 | “最近一次变更/改了什么/变更历史” | 项目、最新版本、变更原因、来源、时间 |
| 待办逾期 | “逾期/超期/过期” | 逾期任务、客户、项目、来源、逾期天数 |
| 其他 | 关键词兜底 | 检索结果 + 明确“仅检索，未推断” |

## 4. 不确定性规则

| 情况 | 等级 | 原因 |
|---|---|---|
| 命中原始沟通/文档 | low | 可逐条定位 |
| 仅需求条目命中 | medium | 缺原始沟通原文 |
| 版本无来源 | medium | 有变更但无法点回来源 |
| 关键词兜底 | medium | 只检索，不生成结论 |
| 无命中 | high | 关键词未命中 |

## 5. 限制

- 关键词是二元组匹配，不做语义向量；同义改写可能漏检。
- 意图识别是正则，换一种问法可能落到关键词兜底。
- 客户提及只统计有 `customer_id` 的命中记录，不根据正文人名猜客户。
- 项目变更依赖 `history.projects[].versions`；没有版本历史就返回 high。
- 待办逾期按 open 状态与日期比较；已完成为完成时间，不看逾期。
- 客户/项目节点的 locator 优先取最近沟通；纯档案节点可能没有原始文件。
- 回答不调用模型，不生成资料中没有的结论。
- 本次未推送 GitHub，仓库仍为 v0.2.0。
