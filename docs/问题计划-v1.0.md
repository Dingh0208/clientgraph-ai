## 1. 固定顺序

| 顺序 | 维度 | 关键字段 |
|---|---|---|
| 1 | 业务目标/指标 | 业务目标、衡量指标 |
| 2 | 用户与流程 | 使用角色、核心流程 |
| 3 | 一期范围 | 本期包含、本期不包含 |
| 4 | 平台与交互 | 平台、交互规范 |
| 5 | 数据迁移 | 来源系统、迁移范围 |
| 6 | 接口与第三方 | 外部接口、第三方服务 |
| 7 | 权限/安全/合规 | 角色权限、安全要求、合规要求 |
| 8 | 性能/可靠性 | 性能指标、可用性 |
| 9 | 工期/预算/合同 | 上线日期、预算、合同主体 |
| 10 | 验收/上线/运维/售后 | 验收标准、上线批准、运维责任、质保期、售后响应 |

顺序固定，不因资料顺序改变。

## 2. 展示规则

- **始终相关**：业务目标/指标、用户与流程、一期范围、平台与交互、工期/预算/合同、验收/上线/运维/售后；
- **条件相关**：
  - 数据迁移：有历史数据或已给出来源系统；
  - 接口与第三方：已给出接口或第三方服务；
  - 权限/安全/合规：有多角色、个人数据或受监管；
  - 性能/可靠性：有性能/可用性事实或面向公众；
- **缺口强制展示**：即使维度条件不满足，只要显式传入 gap，也展示并提问；
- 不相关且无缺口的维度不进入输出；相关但已明确的维度保留（状态 clear，问题为空）。

## 3. 问题规则

- 每题只问一个字段，不把“范围/不做”“验收/上线”混在一句；
- 以“请问”开头，简短、礼貌、专业；
- 一题一个问号；
- 有 gap 时优先使用 gap 原因，否则写“资料未提及”；
- 同一 `(维度, 字段)` 只出现一次；
- 合同字段仅在需要合同时提问；不需要合同不生成该问题。

示例：

- 请问一期用哪些指标衡量目标达成？
- 请问哪些功能明确不在一期范围？
- 请问有没有必须遵循的交互或界面规范？
- 请问项目需要满足哪些行业合规要求？
- 请问一期以哪些可验证条件作为验收标准？

## 4. 验证结果

输入：内部工具项目，已有业务目标、角色/流程、包含范围、平台、上线日期、预算；缺少指标、排除范围、交互、安全/合规、验收/上线/运维/售后。

| 项 | 结果 |
|---|---|
| 展示维度 | 7 个（目标、用户、范围、平台、治理、商务、交付） |
| 隐藏维度 | 3 个（数据迁移、接口、性能） |
| 用户与流程 | clear，无问题 |
| 合同 | 不需要，未生成问题 |
| 问题总数 | 10 |
| 每题 | “请问”开头、单问号、≤45 字、单事项、有原因 |
| 重复 | 无 |
| 显式 gap | 迁移维度被强制展示，问题原因使用 gap 文本 |
| 补齐指标 | 目标维度仍展示，但指标问题消失，状态 clear |

## 5. 限制

- 规则依赖调用方提供 `facts/gaps`；不会从原始资料自动发现所有缺口。
- 维度相关性由固定规则判断；项目类型差异可能需要补充规则。
- 合同字段默认需要合同；`contract_required=false` 时跳过。
- 不生成建议答案，只生成问题与原因。
- 未接前端；当前为 Python 计划输出。
- 问题模板为固定中文，未做多语言。
- 本次未推送 GitHub，仓库仍为 v0.3.0。
