# 澄清问题状态 v1.0

> 日期：2026-11-08
> 状态：四态流转、多次回答快照、追问人工触发已实现并验证（57 项检查通过）
> 代码：`clarification/question_lifecycle.py`、`scripts/verify_question_status.py`
> 证据：`evidence/question-status-2026-11-08.json`

## 1. 四种状态

| 状态 | 中文 | 含义 | 是否处理完成 |
|---|---|---|---|
| `pending` | 待问 | 已生成，尚未发给甲方 | 否 |
| `asked` | 已问 | 已发出，等待回答 | **否** |
| `answered` | 已回答 | 至少有一条回答 | 是 |
| `not_applicable` | 不适用 | 经人工判断无需回答，附原因 | 是 |

处理结论只认 `answered` 和 `not_applicable`。`asked` 无论发出多久都留在未完成列表里，不会被自动视为已处理。

统计口径：

- `open = pending + asked`
- `resolved = answered + not_applicable`
- `open + resolved = questions`

## 2. 状态流转

```
待问 --标记已问--> 已问 --记录回答--> 已回答（可继续追加回答）
  |                  |
  |                  +--标记不适用--> 不适用
  +----------------------------------^
```

约束：

- 已回答、不适用是终态，不能再回到已问，也不能重复标记不适用；
- 未标记已问不能直接记录回答（防止“没问就替客户答”）；
- 已问可以多次标记（换渠道再问），`ask_count` 累加，首次 `asked_at` 与最近 `last_asked_at` 分开保存；
- 标记不适用必须写原因，原因为空直接拒绝。

## 3. 回答与时间快照

每次回答追加一条记录，旧记录不修改、不覆盖：

| 字段 | 说明 |
|---|---|
| `id` / `sequence` | 回答编号与在本题中的顺序 |
| `text` | 甲方回答原文 |
| `answered_at` | 甲方回答时间 |
| `recorded_at` / `snapshot_at` | 录入时间，即该条快照的形成时间 |
| `operator` / `answer_source` | 录入人与来源渠道 |
| `question_text` | 原问题文本快照 |
| `question_priority` | 原问题优先级快照 |
| `question_evidence` | 原问题证据快照 |
| `evidence` | 本条回答引用的相关证据 |
| `status_before` | 记录前的状态 |

引用要求：

- 每条回答必须带 `question_text`，保证问题后来被编辑也能追溯当时问的是什么；
- 回答必须至少有一条证据：优先用本条传入的证据，没有则回退到原问题证据；两者都为空直接拒绝（`E_NO_EVIDENCE`）；
- 所有快照深拷贝，外部后续修改证据对象不会污染已保存的回答。

## 4. 追问规则

- 记录回答**不会**自动生成追问；
- 只有显式调用 `generate_followup()`（对应老板点击“基于回答生成追问”）才创建子问题；
- 未回答的问题不能生成追问（`E_NOT_ANSWERED`），不适用与待问同样不行；
- 子问题初始为待问，继承原问题的维度、字段与优先级，记录 `parent_question_id`、`based_on_answer_id`、`generated_from=followup`；
- 子问题证据 = 原问题证据 + 被引用回答的证据 + 本次补充证据，按定位符与摘录去重；
- 不填追问文本时，按原问题生成一句礼貌追问；老板也可直接输入自己的问法；
- 每次追问都写操作日志（操作人、时间、父问题、回答编号），便于审计。

回答之后的去向见《回答回写 v1.0》：选择目标客户/项目、预览字段变更与证据、人工确认后保存。

## 5. 验证结果

以《问题优先级 v1.0》的演示项目生成 10 个问题，再执行完整交互：

| 场景 | 结果 |
|---|---|
| 初始 | 10 个待问，未完成 10，已完成 0 |
| 标记已问 | 状态已问、`ask_count=1`、仍计未完成 |
| 重复标记已问 | `ask_count=2`，首次时间保留 |
| 未问直接回答 | 拒绝 `E_NOT_ASKED` |
| 无证据回答 | 拒绝 `E_NO_EVIDENCE` |
| 正常回答 | 已回答、计入已完成，回答含原问题文本与证据 |
| 多次回答 | 追加第 2、3 条，序号连续，首条内容不变，`answer` 指向最新 |
| 自动追问 | 回答后子问题数仍为 0，问题总数不变 |
| 显式追问 | 生成 1 个子问题（待问），父问题记录子问题编号与操作人 |
| 待问/不适用生成追问 | 拒绝 `E_NOT_ANSWERED` |
| 不适用 | 必须写原因，计入已完成，不能回答或再标记已问 |
| 快照隔离 | 修改外部证据对象后，已存回答不受影响 |
| 统计 | 12 个问题（含 2 个追问）、未完成 10、已完成 2、回答 3 条，分区一致 |

检查项共 57 项，全部通过。

## 6. 限制

- 未接前端；“标记已问”“记录回答”“基于回答生成追问”目前是接口能力，按钮尚未落到原型页面；
- 不自动判断回答是否充分，追问内容由老板确认或输入；
- 状态不含“已删除”；删除与归档仍走数据字典的软删规则，本次未实现；
- 未做多轮追问链的深度限制，同一父问题可生成多条追问；
- 未推送 GitHub，仓库仍为 v0.3.0。

ledger = QuestionLedger(plan_questions(ctx)["questions"])

                  answered_at="2026-11-06T11:00:00+08:00",

                             "locator": "msg 120"}])
