## 1. 六种状态

| 状态 | 中文 | 判定 |
|---|---|---|
| `draft` | 草稿 | 已建单，未开始分析 |
| `analyzing` | 分析中 | 存在待执行或执行中的批次 |
| `partial` | 部分完成 | 分析结束，已有部分问题有结论，但未全部完成 |
| `incomplete` | 未完成 | 分析结束，仍没有任何问题形成结论（含批次失败） |
| `completed` | 已完成 | 所有问题都已回答或不适用 |
| `archived` | 已归档 | 归档隐藏，可恢复原状态 |

“已问”不算结论：只发出问题、没有回答，仍是未完成。测试中问完 3 个问题后状态仍是未完成，回答 1 个才变为部分完成。

## 2. 状态流转

```
草稿 --确认范围--> 分析中 --批次完成--> 部分完成 / 未完成 / 已完成
                                   ↑
                          追加资料增量分析（显式开始）
已完成 --追加资料--> 仍已完成 --开始增量分析--> 分析中 --> …
任意状态 --归档--> 已归档 --恢复--> 原状态（按问题重新计算）
```

- 开始分析前必须人工确认范围（`E_SCOPE_NOT_CONFIRMED`）；
- 批次全部结束后按问题结论计算状态，不按“批次成功数”冒充完成；
- 已完成记录追加资料不会自动复活，必须显式开始增量分析；
- 归档默认隐藏；恢复时按批次与问题重新计算，不会简单回到“已完成”。

## 3. 筛选

`list_records()` 支持组合条件：

| 参数 | 说明 |
|---|---|
| `customer_id` | 按澄清单快照中的客户过滤 |
| `project_id` | 按项目过滤 |
| `date_from` / `date_to` | 按创建日期闭区间过滤 |
| `view="unanswered"` | 仍有待问或已问未答的问题 |
| `view="completed"` | 状态为已完成 |
| `include_archived` | 默认 `false`，归档单不出现 |
| `include_deleted` | 默认 `false`，已删除工作单不出现 |

返回摘要包含问题数、未完成数、有结论数、客户/项目与时间，按更新时间倒序。

## 4. 复制为新草稿

`copy_as_draft()`：

- 新建独立澄清单，名称默认“原名（副本）”，记录 `copy_of`；
- 复制客户/项目范围与模型参数；
- 复制资料选择，但新单资料均为未分析，不复制分析批次；
- 问题复制为待问，**不复制回答**、不复制冲突与追问结论；
- 原单不受影响，两单后续各自独立。

## 5. 追加资料与增量分析

- `append_materials()` 按来源类型 + 来源 ID/哈希 + 哈希去重，重复资料返回 `duplicates`；
- 新资料标记为未分析，已有问题、回答、状态不变；
- `start_analysis()` 只为未分析资料建批次，批次编号带轮次（如 `R2-B1`），不会重跑旧资料；
- 增量轮次完成后，旧问题保持原结论，新问题进入待问；有旧结论 + 新待问时为部分完成。

## 6. 删除工作单保留原始资料

- `delete_record(confirm=True)` 软删工作单，列表默认隐藏，`include_deleted=True` 可审计；
- 资料快照保留在全局资料表，`all_sources()` 仍能查到，并标记 `record_deleted=true`；
- 删除不物理移除文件、文本快照或其他业务记录；
- 已删除工作单不能归档或继续分析；
- 未传 `confirm=True` 直接拒绝（`E_CONFIRM_REQUIRED`）。

## 7. 文本复制与导出

`render_text(record_id, group_by="customer"|"project", external=False)` 输出可直接复制的文本，按客户或项目分组。

### 7.1 内部版

包含：问题、优先级、回答（时间与回答人）、提问理由、证据（文件 · 定位符 · 摘录）、不适用原因、历史回答条数。

### 7.2 对外版

隐藏：提问理由、证据、不适用原因、置信度与内部模型参数。保留：客户/项目分组、问题、优先级、回答与时间。

### 7.3 Word

`export_docx()` 直接写 OOXML（`.docx`），零第三方依赖：标题、客户/项目层级、问题与回答段落，中文字体微软雅黑，A4 页面。

### 7.4 PDF

`export_pdf()` 先生成 HTML，再调用本机 Edge/Chrome 无头模式打印为 PDF，使用系统中文字体，正文可分页。未安装浏览器时返回 `E_PDF_ENGINE`，Word 导出不受影响。

## 9. 限制

- 未接前端：列表、筛选、归档、复制、导出按钮尚未落到原型页面；
- PDF 依赖本机 Edge/Chrome，无浏览器环境只能导出 Word；
- 文本导出为纯文本，不保留 Markdown 样式；
- 删除为软删，未提供恢复工作单入口（资料始终保留）；
- 归档不冻结内容，恢复后仍可追加资料；
- 多客户/多项目澄清单需在问题入单时带 `customer_id`、`project_id`，否则导出归入“未归属”；
- 一次导出只针对一个澄清单，不支持跨单合并导出；
- 未推送 GitHub，仓库仍为 v0.3.0。

## 10. 复现

```bash
python scripts/verify_clarification_records.py
```

最小用法：

```python
from clarification.workspace import ClarificationWorkspace

ws = ClarificationWorkspace()
record = ws.create_record(
    {"customers": [{"id": "c1", "name": "青岚能装备（虚构）"}],
     "projects": [{"id": "p1", "name": "设备巡检小程序（一期）"}]},
    materials=[{"source_id": "m1", "name": "聊天", "type": "chat",
                "locator": "chat://m1", "text": "一期先做扫码巡检"}],
)
ws.confirm_scope(record["id"])
ws.start_analysis(record["id"])
ws.complete_batch(record["id"], "R1-B1", questions=[{"text": "请问一期包含哪些功能？"}])

print(ws.render_text(record["id"], external=True))
ws.export_docx(record["id"], "澄清单.docx", external=True)
ws.export_pdf(record["id"], "澄清单.pdf", external=True)
```
