## 2. 当前失败路径（预期行为）

| 场景 | 输入 | 实际输出 |
|---|---|---|
| 未知检索 | “有没有提到海外部署” | 结论“未找到相关记录”，`uncertainty=high`，无证据 |
| 无版本项目变更 | “供应链协同最近一次变更是什么” | “暂无变更记录”，`uncertainty=high` |
| 模糊待办日期 | “下周给一版原型” | `due_at=null`、`due_status=pending_vague`，生成“下周具体指哪一天”问题 |
| 应退出时通知 | `app_active=false` | `skipped=app_inactive`，不写发送记录，任务 `reminders_sent` 不增加 |
| 通知器失败 | `FakeNotifier(fail_times=1)` | 1 条失败、不标记已发送，可重试 |
| 未解决冲突 | 预算 8 万 vs 10 万 | `status=must_confirm`，`resolution/model_choice=null`，`write_blocked=true` |
| 跨客户相似需求 | c1 设备巡检 / c2 设备巡检报表 | 关系图仅语义建议，不合并、不改项目归属 |
| 同名客户/项目 | 两个同名客户/项目 | 保留独立 ID；仅 `semantic_similar` 建议，需人工确认 |
| 共享文件多项目 | 同一文件被 p1/p3 引用 | 两条直接边，`project_ids=[p1,p3]`，不强行归档到单一项目 |

## 3. 回归中确认的限制

- 关键词检索是二元组，不做语义向量；“小程序开发”依赖词片段命中。
- 意图识别是正则，未知问法落到关键词兜底。
- 项目变更要求显式项目名；只有“某项目”且存在多个项目时不猜。
- 客户提及只统计有 `customer_id` 的记录，不根据正文人名推断。
- 待办模糊日期、无负责人会保留为待确认，不自动补全。
- 通知策略已实现，但真实 Windows Toast 仍需桌面端接入；测试用 FakeNotifier。
- 版本历史、冲突、关系图、检索均为只读分析层；未实现业务字段自动回写。
