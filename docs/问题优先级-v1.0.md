## 1. 三档优先级

| 档位 | 含义 | 判定口径 |
|---|---|---|
| `must_confirm` 必须先确认 | 阻塞范围、报价或工期 | 该字段未知时，范围无法冻结或无法给出报价/排期 |
| `important` 重要 | 影响方案或成本 | 不阻塞签约，但会改变技术方案、工作量或成本估算 |
| `later` 后续确认 | 可留到交付和运维 | 只影响交付后的服务安排，不影响当前范围与报价 |

字段级映射（`PRIORITY_RULES`）：

| 档位 | 字段 |
|---|---|
| 必须先确认 | 业务目标、本期包含、本期不包含、平台、迁移来源系统、迁移范围、外部接口、上线日期、预算、合同主体 |
| 重要 | 衡量指标、使用角色、核心流程、交互规范、第三方服务、角色权限、安全要求、合规要求、性能指标、可用性、验收标准 |
| 后续确认 | 上线批准、运维责任、质保期、售后响应 |

优先级只看字段本身的影响面，不随资料出现顺序或置信度改变；资料冲突也不会把“后续确认”抬成“必须先确认”，冲突由冲突标记单独表达。

每个问题同时输出：

- `priority`：档位代码；
- `priority_label`：中文档位名；
- `priority_basis`：为什么归入该档（一句话）。

## 2. 每题的证据字段

| 字段 | 说明 |
|---|---|
| `evidence[]` | 原文摘录列表，每项含 `text`、`file`、`source_type`、`locator`、`occurred_at`、`confidence` |
| `excerpt` | 首条原文摘录，便于列表展示 |
| `source_time` | 证据时间，取证据与冲突双方中最新时间；无时间则为 `null` |
| `reason` | 提问理由（原有字段，缺口原因优先） |
| `conclusion_type` | `fact` 事实 / `inference` 推断 / `unknown` 未知 |
| `conclusion_label` | 事实 / 推断 / 未知 |
| `confidence` | 0–1 置信度 |
| `low_confidence` | 是否低于 0.6 |
| `confidence_note` | 低置信度提示文案；正常情况下为 `null` |
| `conflict_evidence` | 冲突双方证据；无冲突为 `null` |

### 2.1 结论标记

- `fact`：资料中存在直接原文，摘录可核对；
- `inference`：只有缺口记录或规则推断，没有直接原文；
- `unknown`：既无原文也无可靠推断，或资料存在未确认冲突。

与 PRD/数据字典取值的对应：`gap` → `inference`（缺口由资料推断得出），`conflict` → `unknown` 加 `conflict_evidence`（决议未定，不写回），`custom` 为人工新增问题，本次未生成。

### 2.2 置信度

| 情况 | 置信度 |
|---|---|
| 有冲突 | 0.30 |
| 未知 | 0.20 |
| 推断 | 0.50 |
| 事实（基础 0.70） | 有来源时间 +0.10；有定位符 +0.10；≥2 条证据 +0.05，上限 0.95 |
| 任一证据自身置信度 < 0.60（如 ASR/OCR） | 封顶 0.55，并标记低置信度 |

低于 0.60 一律 `low_confidence=true`，并给出提示，例如：

- “资料存在冲突且尚未确认，双方证据均保留，未自动选择任何一方”
- “资料中未找到相关原文，该问题基于维度清单提出”
- “原文来自转写或识别，置信度 0.42，建议核对原件”

## 3. 冲突处理

- 冲突可作为 `context.conflicts` 传入，兼容冲突检测模块的 `value_a/value_b/source` 结构，也支持补 `excerpt_a/excerpt_b`；
- 冲突字段自动转为缺口并强制展示对应维度，即使该维度原本被过滤；
- 问题 `reason` 固定为“资料存在冲突，需人工确认”；
- `conclusion_type=unknown`、`low_confidence=true`；
- `conflict_evidence` **完整保留双方**：原始值、归一值、原文、文件、定位符、时间，并固定 `resolution=null`、`write_blocked=true`；
- 不选择任何一方，不写回业务字段。

## 5. 限制

- 优先级为字段级固定规则，未按行业或项目类型细分；
- 证据需由调用方随 `facts/gaps` 一并提供；模块不主动回查原始资料；
- 置信度是规则打分，不是模型概率；
- `inference` 仅表示“有缺口记录但无直接原文”，不代表已核实；
- 冲突识别依赖调用方传入 `conflicts`，本模块不重复做冲突检测；
- 冲突到字段的映射按维度粗粒度处理（如 scope 统一落到“本期包含”），细分到字段需调用方直接给 `field`；
- 同一字段多条冲突会全部保留，未做同类合并；
- 未接前端，当前为 Python 计划输出；
- 本次未推送 GitHub，仓库仍为 v0.3.0。
