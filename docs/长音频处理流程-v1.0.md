# 长音频处理流程 v1.0

> 日期：2026-11-06
> 状态：实现并验证（7 个场景全部通过）
> 代码：`audio_pipeline/`、`scripts/verify_audio_pipeline.py`
> 证据：`evidence/audio-pipeline-2026-11-06.json`

## 1. 目标与边界

把一段长音频稳定地转成**带原始时间偏移与来源的文本片段**，并在单片段失败时保留其余结果。

本版明确不做：

- 不做说话人分离，也不根据文本、音色或轮次推断“我/客户”；
- 不做音频内容理解（摘要、需求抽取）；
- 不修改原始文件，所有派生文件写入运行目录；
- 不把 Mock 结果当作真实 ASR 结果。

## 2. 流水线

```text
原始文件（只读，先记 SHA-256）
   ↓ ffprobe 校验
归一化：16 kHz / 单声道 / PCM s16le
   ↓ ffmpeg segment
固定切片：默认 300 秒，记录每片 start/end 偏移
   ↓ 并发 2（可配置）
ASR：逐片调用（Qwen 或 Mock），单片超时 / 重试
   ↓ 合并
全局时间戳 + 来源（文件、片段、片内偏移、提供方）+ 未识别内容标记
   ↓
result.json（含状态、错误、片段、说话人能力声明）
```

## 3. 归一化与切片

### 3.1 归一化

```bash
ffmpeg -i input -vn -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_s16le normalized.wav
```

- 统一为 16 kHz、单声道、16-bit PCM；
- 归一化后再次 `ffprobe`，校验采样率与声道，不通过则报 `E_NORMALIZE_INVALID`；
- 原始文件只读；归一化产物是派生文件。

### 3.2 切片

```bash
ffmpeg -i normalized.wav -f segment -segment_time 300 \
  -reset_timestamps 1 -segment_list chunks.csv -segment_list_type csv \
  chunks/chunk_%03d.wav
```

- 切片长度固定，重叠为 0；
- 每片的 `start/end` 从 ffmpeg 的 `chunks.csv` 读取，不使用“序号 × 300 秒”假设；
- 实测 1 小时 MP3 的片段起点为 `0, 300032, 600000, 900032, …, 3300032 ms`，存在 32 ms 级偏移。这是 MP3 帧对齐造成的真实边界，合并时必须使用实际偏移；
- 最后一片按实际时长截断。

## 4. 并发、超时与重试

| 项 | 实现 |
|---|---|
| 并发 | `ThreadPoolExecutor(max_workers=concurrency)`，默认 2 |
| 超时 | 每次 ASR 调用单独计时，`future.result(timeout)`；超时抛 `E_ASR_TIMEOUT` |
| 重试 | 每个片段独立重试，最多 `max_attempts`（默认 2）；只重试失败片段 |
| 重试范围 | 不重新归一化、不重新切片、不重跑成功片段 |
| 隔离 | 任一片段失败只标记该片段；其他片段继续 |
| 可观测 | `max_concurrency_observed` 记录实际同时在跑的调用数 |

超时线程无法被强制终止（Python 限制），实现上放弃等待并继续队列；真实 HTTP 调用应同时设置网络超时，避免线程长期滞留。

## 5. 结果合并

### 5.1 时间戳

```text
global_start_ms = chunk.start_ms + segment.local_start_ms
global_end_ms   = min(chunk.start_ms + segment.local_end_ms, chunk.end_ms)
```

- 片段内时间先裁剪到 `[0, chunk.duration_ms]`；
- 合并后按 `start_ms`、`end_ms`、`id` 排序；
- 片段 ID 为 `c{chunk:03d}s{n:03d}`，稳定可追溯；
- 保留 `local_start_ms / local_end_ms`，便于回到片内位置。

### 5.2 来源

每个片段保存：

```json
{
  "id": "c005s001",
  "text": "……",
  "start_ms": 1500032,
  "end_ms": 1596000,
  "chunk_index": 5,
  "source": {
    "file": "long_1h.mp3",
    "chunk_file": "chunk_005.wav",
    "chunk_start_ms": 1500032,
    "provider": "mock",
    "model": "mock-asr-v1",
    "timestamp_source": "segment"
  }
}
```

`timestamp_source` 只有两种：

- `segment`：提供方返回了片段内时间；
- `chunk`：提供方只返回整段文本，此时用整片范围兜底，并在结果中明确标记。

### 5.3 空转写

- 0 字节文件：直接失败 `E_EMPTY_AUDIO`，不进入切片；
- 静音音频：识别完成但 0 个片段，状态 `completed`，追加警告“未识别到语音内容（空转写），原始音频已保留”；
- 空转写不等于失败，也不伪造文本。

## 6. 说话人分离

**本版不提供，也不推断。**

```json
"diarization": {
  "supported": false,
  "status": "not_available",
  "reason": "未配置支持说话人分离的 ASR 模型；所有片段标记 speaker_role=unknown，不推断说话人。"
}
```

每个片段固定：

```json
"speaker_role": "unknown",
"speaker_source": "none"
```

- 不根据“问句/答句”推断角色；
- 不根据音高、语速猜测性别或身份；
- 不使用“我/客户”默认值；
- 只有未来接入明确声明 `capabilities.diarization=true` 的模型，才允许写入说话人字段。

## 7. ASR 提供方

| 提供方 | 说明 | 本次是否执行 |
|---|---|---|
| `mock` | 确定性本地提供方，用于验证流水线 | **是** |
| `qwen` | DashScope OpenAI 兼容转写接口，需 `DASHSCOPE_API_KEY` | **否**（无密钥，未联调） |

Qwen 适配器行为：

- 读取 `DASHSCOPE_API_KEY`、`QWEN_ASR_MODEL`（默认 `qwen3-asr-flash`）、`QWEN_ASR_BASE_URL`；
- 未配置密钥时直接报 `E_ASR_NOT_CONFIGURED`，**不会静默回退到 Mock**；
- 提供方返回 `segments` 时使用其时间；只返回 `text` 时用整片范围兜底并标记 `timestamp_source=chunk`；
- 未验证真实网络、鉴权、限流与返回格式，不能宣称已接入成功。

## 8. 验证结果

环境：Windows x64、Python 3.12.13、ffmpeg 7.1.1、并发 2。全部场景原始文件 SHA-256 前后一致。

| 场景 | 输入 | 结果 | 关键断言 |
|---|---|---|---|
| 1 小时音频 | 3600.039 s，44.1 kHz 双声道 MP3 | `completed`，12 片、36 段 | 归一化 16 kHz/单声道；片偏移 0…3300.032 s；段落均在片边界内；并发 2 |
| 短音频 | 8 s，48 kHz 双声道 | `completed`，1 片、3 段 | 时间落在 0–8000 ms |
| 空音频 | 0 字节 `.wav` | `failed` | `E_EMPTY_AUDIO`；0 片；原件保留 |
| 静音音频 | 5 s 静音，48 kHz 双声道 | `completed`，1 片、0 段 | 明确空转写警告；不伪造文本 |
| 切片失败 | 6 分钟音频，第 2 片注入失败 | `failed` | `E_SEGMENT_FAILED`；保留第 1 片、删除失败片；未调用 ASR |
| 单片段超时 | 6 分钟音频，第 2 片超时，`max_attempts=1` | `partial` | 2 片成功/6 段保留；失败片 `E_ASR_TIMEOUT` |
| 部分重试 | 对上一结果只重试失败片 | `completed`，3 片、9 段 | 尝试次数 `[1,2,1]`；时间戳与来源保持 |

### 8.1 一小时音频的关键数据

| 项 | 值 |
|---|---|
| 原始时长 | 3,600,039 ms |
| 原始参数 | 44,100 Hz / 2 ch / MP3 |
| 归一化 | 16,000 Hz / 1 ch / PCM s16le / 115,200,078 字节 |
| 片段数 | 12（300 s） |
| 片段起点 | 0, 300032, 600000, 900032, 1200000, 1500032, 1800000, 2100032, 2400000, 2700032, 3000000, 3300032 ms |
| 合并段落 | 36 |
| 实际最大并发 | 2 |
| 原始文件 | SHA-256 前后一致 |

### 8.2 超时与重试

- 第一次运行：2 片完成、6 段保留，第 2 片失败（`E_ASR_TIMEOUT`），整体 `partial`；
- 只重试第 2 片：第 2 片尝试次数变为 2，其余仍为 1；
- 重试后 3 片、9 段，`completed`，合并时间戳仍为 `120000–240000 ms` 区间。

## 10. 错误码

| 错误码 | 含义 | 可重试 |
|---|---|---|
| `E_EMPTY_AUDIO` | 0 字节或时长为 0 | 否 |
| `E_NO_AUDIO_STREAM` | 文件无音频流 | 否 |
| `E_PROBE_FAILED` | ffprobe 无法解析 | 否 |
| `E_NORMALIZE_FAILED` | 归一化失败 | 是（检查源文件） |
| `E_SEGMENT_FAILED` | 切片失败 | 是 |
| `E_ASR_TIMEOUT` | 单片超时 | 是 |
| `E_ASR_NETWORK` | 网络异常 | 是 |
| `E_ASR_HTTP` | 服务返回错误 | 429/5xx 可重试 |
| `E_ASR_NOT_CONFIGURED` | 未配置 ASR | 否 |
| `E_ORIGINAL_MODIFIED` | 运行期间原件被改 | 否（必须排查） |

## 11. 限制

- 真实 ASR 未联调：本次全部使用 Mock，Qwen 适配器只完成代码路径，未验证鉴权、限流、返回字段与时延。
- 1 小时音频为合成正弦波，不是真实通话；噪声、方言、多人重叠未覆盖。
- 说话人分离完全未实现，不能用于区分“我/客户”。
- 超时使用线程等待实现，无法强制终止底层调用；生产需依赖 HTTP 超时或进程隔离。
- 切片失败为注入测试，未覆盖磁盘写满、ffmpeg 崩溃、文件被占用等真实故障。
- 并发只有 2，未验证更高并发下的限流与费用控制。
- 结果 JSON 中保留了运行目录内的片段绝对路径，仅用于本地重试；对外交付时应移除。
