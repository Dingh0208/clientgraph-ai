# 已知限制 v1.0

> 日期：2026-11-06
> 适用：第 09–15 轮回归后的当前代码与原型

## 1. 产品与架构

- 单机、单用户原型；无账号、权限、团队协作与云端同步。
- 前端问答为本地规则检索，不调用模型；回答是原文摘录，不是生成结论。
- 导入中心的 2.1 GB 视频、62 分钟音频、200 页 OCR 为界面负载模拟，不代表真实吞吐。
- 所有数据在浏览器 localStorage 或本地运行目录，换设备/清缓存会丢失。
- GitHub 仓库中的演示数据为虚构内容，不对应真实客户。

## 2. 输入格式

- 压缩包只登记原件与哈希，不解压子文件。
- 微信本地数据库未接入；仅支持导出文件、粘贴、截图。
- `.doc` / `.ppt` 依赖 LibreOffice 转换；当前环境未安装，走 `E_LEGACY_FORMAT` 失败路径。
- 密码保护的 Office/PDF/压缩包未支持。
- PDF 只保留行级 bbox，不还原表格结构、多栏阅读顺序。
- 扫描 OCR 仅验证 2.5° 倾斜；低清样本无识别结果；手写体与复杂版式未覆盖。
- 聊天识别为启发式；时间/发送者写在 HTML 属性或非常规分隔符时可能退化为普通段落。
- JSON 只扁平化前 800 个叶子；聊天字段名需落在支持列表内。

## 3. 性能

- OCR 为本地 CPU RapidOCR，单页约 3–19 秒（单次观测）；未做批量并发、GPU、内存压测。
- 长音频只测了 1 小时、并发 2、Mock ASR；真实 Qwen 时延、限流、费用未测。
- 文档解析为毫秒级，但超大表格会截断（XLSX/XLS 5,000 行 × 100 列）。
- 界面 ETA 是按配置速率估算，不是实时测量。
- 未做磁盘写满、文件被占用、进程被杀的故障注入（仅切片失败/超时为注入）。

## 4. 本地诊断

- Sidecar 与微信引擎未随仓库交付；手动启动依赖 `CG_SIDECAR_CMD_JSON` / `CG_WECHAT_ENGINE` 配置。
- `scripts/fake_sidecar.py` 是测试夹具，不是产品 Sidecar。
- 诊断服务仅绑定 127.0.0.1，无鉴权，不能暴露公网。
- 当前环境 OCR 依赖未安装时，状态会真实显示“未安装”，不会伪造正常。
- ASR 默认 Mock，只验证链路；Qwen 未配置、未联调。
- 启动失败策略为最多 2 次、冷却 3 秒、端口冲突不重复拉起；未覆盖系统级崩溃与僵尸进程。
- 日志为本地文本文件，不是不可篡改审计。

## 5. 证据与合并

- 合并要求归一化文本**严格相等**；同义改写不会合并。
- 时间窗口默认 300 秒；跨天/跨客户/跨项目不会合并。
- 无时间的证据只在同一文件内合并，不跨文件猜测。
- 客户/项目识别只覆盖精确手机号、邮箱、微信、名称/别名；昵称、错别字、简称变体不覆盖。
- ASR 无置信度字段，合并时只使用 OCR 置信度。
- 合并后的 `source_type` 取主来源；完整来源需读 `sources[]`。
- 哈希包含时间窗口，换窗口会产生新哈希。

## 6. 待归档

- 操作人固定为“王工（我）”，没有登录身份。
- 归档记录存 localStorage，不是后端审计。
- 批量操作对全部勾选项写入同一目标，不支持批量后逐条覆盖。
- 归档不自动写入客户时间线（原型未实现联动）。
- 忽略是软状态，不删除原件；没有永久删除入口。

## 7. 测试与发布

- 所有验证为单机单次，未做多浏览器、移动端、无障碍专项。
- 真实客户资料、平台密钥、截图未进入仓库；仓库只包含虚构语料与代码。
- 尚无 CI、签名安装包、自动更新与生产监控。
- v0.1.0 的历史文档仍保留；本轮以 v0.2.0 为当前基线。
