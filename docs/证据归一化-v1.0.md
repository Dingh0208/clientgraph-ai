# 证据归一化 v1.0

> 日期：2026-11-06
> 状态：实现并验证（22 项检查全部通过）
> 代码：`evidence_layer/`、`scripts/verify_evidence_layer.py`
> 证据：`evidence/evidence-layer-2026-11-06.json`

## 1. 目标

把 ASR、OCR、Office、邮件、聊天等不同来源的结果，统一成**可引用、可核对、可合并**的证据片段：

- 每条证据都能回答：来自哪个文件、什么类型、属于哪个客户/项目、什么时候、原文是什么、页码或时间点在哪、置信度多少、哈希是什么；
- 同一事实跨来源出现时合并为一条，但保留全部来源引用；
- 相似内容只要客户、项目或时间不同，就绝不合并。

## 2. 统一字段

| 字段 | 说明 |
|---|---|
| `id` | `ev_` + 证据哈希前 12 位 |
| `text` | 原文（保留标点与措辞） |
| `normalized_text` | NFKC + 小写 + 去空白/标点，用于严格判等 |
| `text_hash` | 归一化文本的 SHA-256 |
| `hash` | 证据哈希：文本 + 客户 + 项目 + 时间窗口，SHA-256 |
| `source_type` | asr / ocr / document / table / slide / email / chat |
| `source_file` | 主来源文件 |
| `customer` | 唯一确定的客户；不唯一时为 null |
| `customer_candidates` | 客户候选数组（id、name、method、confidence） |
| `project` | 唯一确定的项目；不唯一时为 null |
| `project_candidates` | 项目候选数组 |
| `occurred_at` | ISO-8601 时间（默认 +08:00），未知为 null |
| `time_precision` | second / minute / day |
| `page` | 页码或幻灯片页；无页码为 null |
| `timestamp` | 音视频时间戳 `{start_ms, end_ms}` |
| `bbox` | OCR/版面区域 |
| `confidence` | 置信度（当前来自 OCR；ASR 无置信度时为 null） |
| `confidence_avg` | 合并后各来源置信度均值 |
| `sources[]` | 全部来源引用，见下 |

每个来源引用：

```json
{
  "source_type": "asr",
  "file": "call_0922.mp3",
  "file_hash": "a…",
  "locator": "file://call_0922.mp3#t=120000-125000",
  "occurred_at": "2026-09-22T09:20:00+08:00",
  "page": null,
  "timestamp": {"start_ms": 120000, "end_ms": 125000},
  "confidence": null,
  "hash": "37a7…",
  "meta": {"provider": "mock", "model": "mock-asr-v1", "chunk_index": 0}
}
```

## 3. 来源类型映射

| 输入 | source_type | 页码/时间 |
|---|---|---|
| 音频 ASR 段落 | asr | `timestamp` |
| 视频 ASR 段落 | asr | `timestamp` |
| PDF 文本层 | document | `page` |
| PDF/图片 OCR | ocr | `page`、`bbox`、`confidence` |
| DOCX 段落/标题 | document | 文档时间（若有） |
| DOCX/XLSX/XLS/PPTX 表格行 | table | `page`（PPT 为 slide）或 sheet |
| PPTX 文本/备注 | slide | `page` = slide |
| 邮件正文/附件 | email | `occurred_at` = Date |
| 聊天消息 | chat | `occurred_at` = 消息时间 |

## 4. 客户/项目候选

解析顺序：

1. 调用方传入的 `hints`（导入时已知归属）→ confidence 1.0，method `manual`；
2. 精确手机号（归一化数字）→ 0.98；
3. 精确邮箱（小写）→ 1.0；
4. 微信号 → 0.95；
5. 客户全名 / 别名 → 0.9 / 0.85；
6. 项目全名 / 别名 → 0.9；
7. 文件名与邮件头也参与匹配。

规则：

- 只有一个候选且置信度 ≥0.8 时才写入 `customer` / `project`，否则为 null，候选全部保留；
- 项目候选若与已确定客户的 `customer_id` 不一致，会被过滤；
- 多客户命中时不猜，避免把资料挂错。

## 5. 时间与合并窗口

- 时间统一转 ISO-8601，无时区按 +08:00；
- 精度保留 second / minute / day；
- 合并窗口默认 **300 秒**：同一事实的 ASR 与聊天时间相差 30 秒可合并；
- 没有时间的证据（如部分 OCR）**只在同一文件内合并**，不跨文件合并，避免误并；
- 文档使用 `meta.created` 作为文档时间；聊天用消息时间；邮件用 Date 头。

## 6. 合并规则

### 6.1 合并条件（全部满足）

1. 归一化文本完全相等（不是相似）；
2. 客户 key 相同；
3. 项目 key 相同；
4. 时间差 ≤ 300 秒（或同文件且都无时间）。

### 6.2 不合并

- 文本相似但不相等：`预算8万` 与 `预算大概8万左右` 分开；
- 同一文本、不同客户：分开；
- 同一文本、不同项目：分开；
- 同一文本、不同日期/超出窗口：分开；
- 客户候选不唯一（如同时命中两个客户）：不与已确定客户的证据合并。

### 6.3 合并后

- 保留全部来源（按文件、locator、来源哈希去重）；
- `text` 取置信度最高（并列取更长）的来源原文；
- `confidence` 取最大值，`confidence_avg` 取均值；
- `page`/`timestamp`/`bbox` 取主来源，缺失时从其他来源补；
- `hash` 由「文本 + 客户 + 项目 + 时间」决定，输入相同则稳定。

## 8. 限制

- 合并判等是**严格文本相等**，不做语义相似；同义改写不会合并（这是有意的，避免误并）。
- 客户/项目识别依赖精确手机号、邮箱、微信、名称或调用方 hints；昵称、简称、错别字未覆盖。
- 300 秒窗口是默认值，可通过参数调整；跨天相同事实不会合并。
- 文档时间使用 `meta.created`，不代表沟通发生时间；对无时间的 OCR/表格，可能没有 `occurred_at`。
- ASR 当前没有置信度，`confidence` 为 null；合并时只使用 OCR 置信度。
- 合并后的 `source_type` 取主来源；多来源类型需读取 `sources[]`。
- 哈希包含时间窗口，同一事实换一个时间窗口会得到新哈希；这是“不同时间不合并”的必然结果。
- 未实现证据去重的人工确认、冲突裁定与回写，只做归一化与合并。

```json
  "window_seconds": 300
}
```

```bash
python -m evidence_layer.cli --input bundle.json --out evidence.json
```
