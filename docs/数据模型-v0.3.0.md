# 数据模型 v0.3.0

> 日期：2026-11-06
> 范围：客户 360、需求抽取与版本、冲突、风险、待办、关系图、统一检索
> 原则：所有跨对象查询按 `customer_id/project_id` 过滤；语义相似只建议，不合并。

## 1. 实体

| 实体 | 关键字段 | 归属 | 时间 | 来源 | 状态/删除 |
|---|---|---|---|---|---|
| Customer | id, name, aliases, contacts, phone, email, wechat | 根 | created_at | 导入/新建 | active/archived |
| Project | id, customer_id, name | 客户 | created_at | 导入/新建 | active/won/lost/archived |
| Communication | id, customer_id, project_id, channel, text, file_id, locator | 客户/项目（可空=待归档） | occurred_at | 导入 | 软删除 |
| File | id, name, sha256 | 沟通（可空） | imported_at | 原件只读 | 软删除 |
| Document | id, customer_id, project_id, title, text, locator | 客户/项目 | occurred_at（可空） | 解析 | 软删除 |
| Requirement | id, customer_id, project_id, title, description, deadline, owner | 项目 | created_at | 抽取/人工 | 待确认/已确认/已取消 |
| RequirementVersion | requirement_id, version, status, changes, sources | 需求 | occurred_at/recorded_at | 追加 | 不可修改 |
| Risk | id, customer_id, project_id, title, level, evidence_ids | 客户/项目 | created_at | 抽取/人工 | open/closed |
| Conflict | id, customer_id, project_id, requirement_id, value_a/b, sources | 客户/项目/需求 | detected_at | 冲突检测 | must_confirm/resolved |
| Task | id, customer, project, owner, due_at, priority, status, risk, source | 客户/项目（可空） | due_at/created_at | 下一步动作 | open/done/cancelled |
| Evidence | id, text, locator, source_type, source_id, occurred_at | 客户/项目 | occurred_at | 解析/导入 | 不可独立删除 |
| RelationshipEdge | from, to, type, why, evidence, requires_confirmation | 两端实体 | created_at | 直接/语义/人工 | 只追加 |
| SearchRecord | entity_type, entity_id, text, locator, occurred_at | 继承实体 | — | 索引 | 随实体 |

## 2. 关系

```text
Customer 1─n Project
Customer 1─n Communication
Project 1─n Communication
Communication 1─n File（引用）
Project 1─n Requirement
Requirement 1─n RequirementVersion
Customer/Project 1─n Risk
Customer/Project 1─n Conflict
Customer/Project 1─n Task
Evidence n─1 Communication/File
RelationshipEdge 连接任意两类实体
```

- 需求的 `customer_id` 必须等于项目所属客户；冲突/待办同理。
- 一条沟通只属于一个项目；未归属时 `project_id=null`，进入待归档。
- 一个文件可被多个项目通过不同沟通引用，不写单一 `project_id`。
- 证据必须带 `locator`；没有 locator 不进入检索与关系图。

## 3. 时间与版本

- `occurred_at` 是业务发生时间；`recorded_at/created_at` 是入库时间。
- 时间缺失显式保存为 null，界面显示“时间未知”，不伪造。
- 需求/项目版本只追加；旧版本保留，最新版本为当前结论。
- 新资料未提及的字段沿用上一版；明确变化才产生新版本。

## 4. 隔离规则

1. 所有查询先按 `customer_id`/`project_id` 过滤，再做文本匹配。
2. 同名客户/项目保留独立 ID，不按名称合并。
3. 语义相似只生成 `semantic_similar` 建议边，`requires_confirmation=true`，不改变归属。
4. 跨客户相似需求不合并、不互换项目。
5. 冲突按 `(project_id, dimension, requirement_key)` 分组，不跨项目。
6. 待办完成/延期只影响目标任务，不级联到其他客户/项目。
